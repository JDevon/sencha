SavedSource

One store of saved player data, such as a DataStore wrapper, created with Sencha.savedSource. Saved replicators are created from it, and the server connects it to the store with SavedSource:setFetchFunction and SavedSource:replicateChanges.

Sencha doesn't depend on any data store library. A game with two stores creates two sources, and they never interfere.

In Studio, the source's GreenTea type also checks the data it receives, and warns once if it doesn't match.

Functions​

replicator​

</>
SavedSource:replicator(
valueType: GreenTeaType,
lookup: (savedData: D) → T,
incrementalConfig: SavedIncrementalConfig<T,P>?
) → SavedReplicator<D,T,P>

Creates a SavedReplicator for the part of the saved data that lookup returns. The saved data passed to lookup is fully typed from the source's GreenTea type. 

researchReplicator = PlayerDataSource:replicator(gt.array(gt.string()), function(playerData)
	return playerData.research
end),

lookup must return an existing table from the saved data, or a primitive, and must not yield. Changes are found by comparing what it returns, so a lookup that builds a new table counts as changed on every save.

setFetchFunction​

This item only works when running on the server. Server
</>
SavedSource:setFetchFunction(fetchAsync: (player: Player) → D?) → ()

Sets the function that returns a player's saved data, yielding until it has loaded, or nil if it never loads. Replicators from this source wait for it to be set. 

PlayerDataSource:setFetchFunction(function(player)
	local didLoad, playerData = PlayerDataServer.waitForPlayerData(player)
	return if didLoad then playerData else nil
end)

replicateChanges​

This item only works when running on the server. Server
</>
SavedSource:replicateChanges(
player: Player,
newData: D,
oldData: D?
) → ()

Tells the source that a player's saved data changed, including when it first loads (oldData is nil). Each replicator whose part changed sends it to the player, then fires its onChanged. Call it from your store's change callback. 

PlayerDataSource:replicateChanges(player, newData, oldData)
